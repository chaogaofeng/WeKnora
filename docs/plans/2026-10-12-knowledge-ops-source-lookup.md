# 来源补查与诊断详情调整

用户已确认：保留回答时证据，收拢技术信息；隐藏不适用且无材料、无缺口的来源区块；补查优先引用与相关段落，预算集中配置。

本轮限定在知识运营模块及其专用装配文件，不改公共检索、Wiki CRUD 或数据库结构，不合并 main。

- [x] 详情：候选记录和运行信息放进同一技术排查折叠区；原始证据保持独立入口。仅在无核验任务、无材料、无缺口且不适用时隐藏来源区块，历史版本单独判断。
- [x] 预算：新增模块内 `SourceLookupPolicy`，默认补查 48,000 字符、每份文档最多 32 片段，保留每页 8 份文档、32 个关联页面和 15 秒补查时限。支持有范围限制的部署环境变量；每份新报告记录生效预算，旧报告不回填。
- [x] 选材：限定已授权的关联原文和有效片段；优先明确片段引用，无引用时依据问题及回答文本的有限关键词排序，按批次加入相邻上下文。关键词仅用于选材，不能证明一致性；任何范围未覆盖仍记录限制。
- [x] 覆盖：后部相关段落、相邻限定条件、明确引用、跨文档预算、租户隔离、配置边界；来源空态、历史版本和隐藏版本提示不掩盖真实缺口。
- [x] 验证：知识运营 Go 测试与竞态检查、SQL 的 PostgreSQL/SQLite 兼容性、前端回归/类型构建、独立复审。仅做只读实际数据核对，不批量重跑历史诊断。
