# 知识运营模块风格与合并收敛实施计划

> 执行方式：superpowers:subagent-driven-development；用户已批准上一轮评估中的优化方案，持续执行并在完成后验收。

**目标：** 对齐现有产品组件和设计变量，减少本模块新增的主干冲突；保留已有业务与权限语义。
**基线：** 功能分支 9becf6a21；官方 upstream/main 1912ba26c；方案 docs/plans/知识运营模块方案.md v1.2。
**架构：** 保持独立 knowledgeops 后端与 views/knowledge-ops 前端，不分散业务实现，不新增全局框架。调用处只保留必要来源与生命周期采集。
**技术：** Go/Gin/GORM、Vue 3/TypeScript/TDesign、现有 app/td 设计变量。

## 约束

- 不处理历史问答，不修改知识，不操作已有数据库，不推送或合并共享分支。
- 风格基准为 KnowledgeBaseList.vue、TenantMembers.vue、EmptyState.vue 及 assets/theme/theme.css；不改全局 token 定义来迁就本模块。
- 保持三类问答、来源撤权、采集边界、诊断分流、独立版本复核及跨租户异步隔离。
- 已应用的迁移不得重写；本分支未交付的模块迁移按最新官方空闲序号安排，文档给出已有测试库处理边界。
- 仅在隔离临时目录验证与主干的组合；现有用户工作区不改变。

### 接入收敛

- Session 删除重复可选构造参数，保留容器初始化时的 setter 注入。
- 流式回答在模块专用、当前 goroutine 私有的 EventBus 包装器观察实际展示事件。原事件及共享 bus 不变；采集不再插入 response.Done、错误、decoder flush 的实现细节。
- 模型输入仍在实际编码后采集；父/祖父/合并来源仍在实际内容组合位置保留身份。
- 以上改动使当前官方主干的回答截断兜底可自动合入，专项确认采集答案等于其最终展示文本。

### 后续可重复预检

```sh
git fetch upstream main
python3 scripts/check_knowledge_ops_merge.py --target upstream/main
```

脚本只检查已提交代码，不修改工作区或 Git index；输出目标 SHA、全部/基线/新增文本冲突，以及实际合并树中的迁移版本碰撞。只要仍有任意冲突就返回 1（包括基线遗留冲突），避免误报整分支可直接合并。`--source` 和 `--baseline` 可显式指定比较提交。将来官方主干可能再次占用迁移号或修改接入契约，应在每次集成前复跑预检和相关测试。
