# 知识运营模块 v1.2 复审记录

日期：2026-09-28。工作分支：`codex/knowledge-ops-v12`。本轮基于 `3adf9905` 复审已实现代码，修复可复现问题并调整实际前端；方案仍为 v1.2。

## 本轮发现与修复

| 问题 | 影响 | 修复与验证 |
|---|---|---|
| RAG 合并片段遗漏贡献来源的权限依赖 | 某个被合并的 chunk 被禁用后，仍可能从运营记录读到它的文本 | 保留 SubChunkID，以及实际合并/父级扩展位置的来源身份；每次读取核对全部依赖。依赖持久化中断时拒绝运营读取，原问答继续遵循 fail-open |
| 采集只截取 chunk，丢弃外层 document 信息 | 地域、有效期等适用条件可能未进入验证输入，造成错误诊断 | 同步保留该 chunk 所在 document 的头部与元数据，不复制其他 chunk 正文；覆盖适用条件及相邻来源隔离回归 |
| 输入缺失仍可得出“不支持” | 将“没采到”误解为“原证据没有支持” | 采集不完整时，整体及论断中的 unsupported 降为 unverifiable；直接的支持或矛盾证据仍按原约束处理 |
| 设置抽屉跨租户异步响应串写 | A 租户旧响应覆盖 B 的草稿，可能将旧设置保存到 B | 请求绑定租户和抽屉生命周期；切换、关闭、卸载后丢弃过期加载及保存响应 |
| 重诊断响应污染另一案例 | 对 A 提交重诊断后切到 B，B 会错误显示已排队 | 重诊断、复核及其刷新绑定原案例、租户和抽屉版本；成功及失败响应都需仍匹配当前上下文 |
| 只能确认首个机器根因候选 | 确认第二候选被迫记作人工纠正，影响抽检纠正计数 | 提供候选选择，确认时保留候选的分类、状态和 confirmed 动作 |
| 历史分析混入后续事后材料 | 复核旧版本时容易把后来获取的资料误当旧版依据 | 仅展示所选报告明确引用的事后证据，包括反对证据；说明这些引用不代表该版全部诊断输入。原始模型输入与候选来源继续按当次问答共享 |

前端异步、候选确认和历史引用用例均先复现失败，再验证修复。测试使用实际 Vue 组件 setup 逻辑，另由页面 smoke 验证真实组件渲染和提交。

## 前端调整

- 统一页面留白、标题、卡片边界、表头、按钮和状态标签；保留既有绿色品牌色，减少大面积高饱和背景。
- 待复核卡片突出问题、风险、诊断摘要和待裁决点；问题组数量及单例独立复核规则保持清晰。
- 详情将来源 ID 和调用信息折叠，证据正文更易阅读；回答与根因仍分开提交。
- 复核表单使用现有 TDesign 控件；设置按采集、自动记录与抽检、诊断预算分组。
- 重新检查浅色、深色、900px 待复核和 800px 概览。深色通过应用本身的主题切换入口验证。

## 实现边界与后续合并

新诊断策略版本为 `knowledge-ops-v1.2-2`；重诊断可能按新策略重新抽样，旧分析保留原版本与抽检概率。

本轮没有新增数据库迁移。主要修改集中在知识运营后端、前端模块及其测试；为保留真实来源身份，RAG 的 `merge.go` 与 `merge_overlap.go` 增加了少量采集调用。合并 main 时需检查这些调用仍位于真实内容合并处，不要把当前数据库来源冒充历史来源。前端没有替换全局设计系统，也没有改无关业务页面。

当时运行配置的安全快照尚未实现。已有模式、Agent、模型标识不等于完整配置快照；报告明确配置归因未核验，不能声称能够精确重放或证明提示词/工具配置导致问题。配置未知与答案来源是否完整分开表达，避免把所有新问答一律降为缺证。

事后补查材料尚无逐分析版本的完整输入快照，因此历史页仅展示报告明确引用的材料。真实模型业务准确率校准、生产规模压测仍未完成；自动记录默认关闭。历史回填和知识写入仍不在范围内。
